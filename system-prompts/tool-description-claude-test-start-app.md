Ask the person, in a dialog of Claude Code's own, whether their app should be started with the ONE start command "ct.mjs status" printed for it, or with a command the person typed as their answer (typed: true). It only asks: it never starts anything. A command the person typed is never started without this dialog's Accept. It asks nothing until the app's address is allowed for this project on this machine (the address dialog of ${ALLOW_ADDRESS_TOOL} comes first). Call it from the person's own conversation only where the run skill says so (section 3, step 2, up: false, when the check answered with startDialog), with project as devServer.check.arguments.project, command and line as devServer.startCommand and devServer.startLine, all exactly as status printed them, and sandbox and background as the words the run skill was loaded with. The helper works the command and its line out again from the project's own files, as status does, and asks nothing about any other. The dialog ends in Accept and Decline, and its last lines say what each does; an Accept also lets later runs start this same command, in the same folder of the same project on this machine, with no dialog, while the project files it runs are unchanged; where the helper cannot tell what the command runs, its Accept covers this time only. The answer is "start" (Accept: start it; with remembered: true, the person accepted this very start earlier and no dialog was shown), "declined" (Decline: they start it, or say where it runs), or answer null when neither came (the dialog was closed or timed out). Where Claude Test starts nothing (background none, or sandbox stays-unreachable or stays-no-listen-fixed), the same call asks the person to start it in another terminal with that line instead: Accept is "it's running now, check again", and the helper checks again before it answers ("recheck", with that new check's fields), Decline is "stop". After four questions that ended without a yes (a Decline counts) it asks no more in this session. A background run never calls it.
